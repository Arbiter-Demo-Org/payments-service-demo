# Arbiter — YC Demo Video Runbook (~60–90s)

The wedge: **deterministic authorization before promotion of consequential
AI-agent actions.** One narrow moment. Austere, terminal-first, no
overproduction. The viewer should feel *"of course enterprises will need this,"*
not *"impressive architecture."*

> Read as authorization infrastructure — not DLP, not observability, not "a
> blocker." Arbiter governs **where a change lands and what approval is missing**,
> never the code content. Do not imply it reads the code body.

---

## Before recording (one-time setup)

- Working tree clean; `payments/settlement.py` at baseline (`MAX_RETRY_ATTEMPTS = 3`),
  `.ai/evidence/` empty, no `arbiter-artifact.json`. (Re-run "Reset" below anytime.)
- Terminal: dark theme, large font, high contrast, **single pane** (no tmux/splits).
- If the Arbiter CLI bundle ever needs rebuilding:
  `cd ../control-plane && npm run build:standalone && cp dist-standalone/cli.js ../payments-service-demo/tools/arbiter.js`
- Migration transient: until the control-plane HMAC-removal Phase 3 re-vendor lands,
  `tools/arbiter.js` may still print a legacy `sig:` suffix. Do not use that suffix
  as demo truth; rely on decision/rationale lines.

### Reset to a clean take
```bash
git checkout -- payments/settlement.py
rm -f .ai/evidence/change-ticket.json arbiter-artifact.json
```

## The shot list

### Beat 1 — Agent makes a routine change (0–12s)
Run Claude Code and ask for a small, plausible edit:
> "Update payout retry logic for settlement failures."

It edits `payments/settlement.py` (e.g. `MAX_RETRY_ATTEMPTS` 3 → 5). Keep the diff
to one or two lines — it should read instantly as *small AI change touching
sensitive payment logic*.

**VO:** "AI agents are starting to ship changes to production-critical systems."

### Beat 2 — PR opens (12–22s)
Brief GitHub screen: PR title + "Generated by Claude Code" + the changed path
`payments/settlement.py`. No browsing, natural branch name (e.g.
`fix/payout-retry`). *(Hybrid only — see "GitHub hybrid shot" below. Skip for a
pure-terminal cut.)*

**VO:** "Here, one touches payment settlement logic."

### Beat 3 — Arbiter decides (22–42s) — core moment
```bash
npm run evaluate
```
Output (instant, <0.2s):
```
  ARBITER  ·  payments-service

  DECISION   DENIED
  Protected path payments/** requires change_ticket evidence before merge.

  artifact: ./arbiter-artifact.json
```
The artifact path / decision are **visible but not narrated**.

**VO:** "Arbiter requires authorization before this can merge."

### Beat 4 — Rationale (42–52s)
Let the one-line rationale sit on screen. (Hybrid: same line appears as the PR
check / merge blocked.)

On screen: *Protected payment logic requires approved change-ticket evidence
before merge.*

### Beat 5 — Add the approval (52–64s)
```bash
cp tools/sample-change-ticket.json .ai/evidence/change-ticket.json
```
(The ticket is a realistic ServiceNow-style approval — ticket id, approver,
timestamp. Don't dwell on it.)

**VO:** "The approved change ticket is attached."

### Beat 6 — Re-run → ALLOW (64–75s) — the payoff
```bash
npm run evaluate
```
```
  ARBITER  ·  payments-service

  DECISION   ALLOWED
  Authorization satisfied for payments/** — required evidence present.

  artifact: ./arbiter-artifact.json
```
Hold on the ALLOW slightly longer than the DENY — this is what keeps Arbiter from
feeling anti-velocity.

**Closing line (VO + on-screen):**
> "Arbiter governs sensitive AI actions before they reach production.
> Agents propose. Arbiter decides."

---

## Narration & visual discipline
- Spoken lines carry ONE idea: *Arbiter made an authoritative decision before
  promotion.* Don't say "artifact details," "reason code," "deterministic" in a row
  — they're on-screen credibility, not voiceover.
- The blocked state appears instantly — no waiting, scrolling, or intermediate logs.
- Provenance (`.ai/provenance.json`) stays quiet in the background — never narrated.
- No cinematic transitions, zooms, motion graphics, soundtrack, or terminal effects.
- Record multiple takes at different pacing; pick the calmest one.
- Acceptable first impression: *"branch protection for AI agents."* The ALLOW payoff
  earns the second-order *"wait, this is deeper than a gate."*

## GitHub hybrid shot (optional, for the blocked-merge visual)
The terminal flow above is the credibility spine and is fully self-contained. To
also show a real blocked merge:

1. Publish the Arbiter action (the `control-plane` repo) and update
   `.github/workflows/arbiter.yml` (`uses: <your-org>/arbiter@<tag>`).
2. Push this repo to GitHub.
3. Branch protection on `main`: require the **Arbiter** status check.
4. Open the PR from the agent's branch → the Arbiter check fails → **merge
   blocked**. Push the change-ticket file → check passes → merge enabled.

Keep GitHub to a single screen; the terminal stays the anchor.

---

## What this demo deliberately does NOT show
- No content/secret/PII scanning (Arbiter gates on path + provenance + evidence,
  not code content).
- No replay / "boundedness" / governance-philosophy beat — that recategorizes the
  product for a generalist audience. Reserve it for technical/investor deep-dives.
